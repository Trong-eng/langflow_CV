Hãy tưởng tượng bạn bước vào một nhà hàng quen thuộc và gọi một món ăn cố định (gọi API thực thi pipeline):

Quy trình vô lý ở nhánh main: Mỗi lần khách gọi món cơm sườn, đầu bếp lại bắt khách mở cuốn sách dạy nấu ăn ra. Đầu bếp ngồi đánh vần từng chữ cái, tra từ điển ngữ pháp (ast.parse()), rồi dịch cuốn sách từ tiếng Anh sang tiếng Việt (compile() ra bytecode), sau đó mới chịu nấu!

Khách thứ hai, thứ ba, thứ một nghìn vào gọi đúng đĩa cơm đó... đầu bếp vẫn lặp lại đúng chu trình đánh vần và dịch sách đó từ đầu!

⚠️ Hậu quả: Đầu bếp kiệt sức vì làm việc thừa mứa, khách hàng phải chờ đợi lâu dù món ăn không đổi.

⚙️ BẢN CHẤT KỸ THUẬT & COMPUTER SCIENCE
  • Mã nguồn lưu dưới dạng chuỗi Text (String) trong Database: Custom Component trong Langflow là script Python lưu trong DB, không phải file .py tĩnh trên đĩa cứng. Trình thông dịch Python không thể tự động sinh file cache .pyc như import thông thường.
  • Duyệt cây cú pháp AST (Abstract Syntax Tree): Khi chưa có artifact được tái sử dụng, worker phân tích source và dựng cây AST để kiểm tra cú pháp và chú thích kiểu.
  • Biên dịch Bytecode lặp đi lặp lại: Tiếp tục gọi hàm compile() để sinh đối tượng CodeType. Việc lặp lại trên cùng source tạo thêm công việc cho worker; tỷ trọng chi phí cần được đo, không suy ra chỉ từ số request.

📦 COMPONENT COMPILATION CACHE ARCHITECTURE component_compilation_cache.py 
# 1. ĐỊNH NGHĨA ARTIFACT BIÊN DỊCH AN TOÀN TRONG RAM
@dataclass(frozen=True, slots=True)
class ComponentCompilationArtifact:
    source: str                     # Chuỗi source code Python gốc
    generation: int                 # Phiên bản generation hợp lệ
    module_template: bytes          # Template AST module đã serialize qua pickle
    class_name: str                 # Tên class Component (VD: SCRFDNode)
    compiled_class: CodeType        # Bytecode đã compile sẵn - nạp thẳng vào runtime
    trusted_vector_store_alias: str | None

# 2. BĂM SHA-256 CỦA SOURCE CODE ĐỂ LÀM KHÓA TRUY VẤN DUY NHẤT
def _source_digest(source: str) -> str:
    return hashlib.sha256(source.encode("utf-8", errors="surrogatepass")).hexdigest()

# 3. QUẢN LÝ CACHE TRONG RAM: THREAD LOCK TRÁNH RACE CONDITION + GIỚI HẠN LRU
_cache: OrderedDict[_CacheKey, _CacheEntry] = OrderedDict()
_cache_lock = RLock()  # Khóa luồng an toàn khi nhiều worker thread truy cập đồng thời

def get_or_build_component_artifact_with_status(source, builder, *, variant=""):
    key = (COMPONENT_COMPILATION_ARTIFACT_GENERATION, _source_digest(source), variant)
    with _cache_lock:
        cached = _cache.get(key)
        if cached is not None and cached.source == source:
            _cache.move_to_end(key)  # Đánh dấu vừa truy cập (LRU)
            return ComponentArtifactLookup(artifact=cached.artifact, retained=True)

        # Nếu chưa có (Cache Miss): chuẩn bị artifact rồi lưu; có thể miss lại sau eviction
        artifact = builder()
        _cache[key] = _CacheEntry(source=source, artifact=artifact)
        return ComponentArtifactLookup(artifact=artifact, retained=True)
ℹ️ Tính toàn vẹn: Khóa gồm generation, SHA-256 của source và variant; cache kiểm tra thêm source khớp entry. Source thay đổi sẽ không tái sử dụng artifact của source cũ. Đoạn code trên rút gọn phần cờ bật/tắt, giới hạn LRU và counter.

# 2. MINH HỌA INTERVAL UNION (logic thực nằm trong protocol.measure_overhead)
def interval_union_ms(intervals: list[tuple[float, float]]) -> float:
    total = 0.0
    right = float("-inf")
    for start, end in sorted(intervals):
        total += max(0.0, end - max(start, right))
        right = max(right, end)
    return total  # Hợp các khoảng output method của 4 node SCRFD; interval tính bằng ms

⏱️ 2. Latency Thực Tế & Langflow Overhead

Server/client API là latency chính của bước /run. Langflow overhead là "thuế điều phối của framework" (framework coordination tax) — đo lường thời gian Langflow dành cho routing, AST parse/compile, khởi tạo Graph, cấp phát bộ nhớ, serialize JSON... sau khi trừ hợp thời gian output method của bốn node xử lý SCRFD.

langflow_overhead_ms = server_total_ms - scrfd_processing_ms
• server_total_ms: Wall-clock từ điểm vào ASGI ngoài cùng đến khi gửi xong response body cuối; loại background work sau response.
• flow_api_ms: Client gọi /run đến khi đọc xong response bytes bằng requests.Session có tái sử dụng TCP.
• scrfd_processing_ms: Độ dài hợp các interval output method của 4 node SCRFD: preprocess, inference, vẽ/lưu ảnh; không cộng trùng overlap. Upload/download, kiểm tra output, counters và RSS ngoài hai clock; latency /run không phải toàn hành trình upload→download. Overhead chỉ giải thích, không thay hai latency thực tế.
⭐ METRIC ƯU TIÊN CHO MỤC TIÊU NÀY: p95
Vì sao đọc p95 cùng mean trong đề tài này?
  • p95 là ngưỡng mà khoảng 95% mẫu latency không vượt quá. Nó mô tả phần chậm của phần lớn request mà mean có thể che khuất; không phải latency của 95% người dùng.

Chọn p95 Làm Chỉ Số Ưu Tiên Như Thế Nào?

Giảm overhead ở phần chậm của phần lớn request; dùng mean và RAM để kiểm tra sự đánh đổi

p95 + mean + RAM
Vì sao chọn p95?

Mục tiêu là giảm latency /run của phần lớn request, kể cả những request chậm hơn mức điển hình. p95 bổ sung thông tin mà mean không thể hiện. Đây là lựa chọn theo mục tiêu đề tài, không phải chỉ số tốt nhất cho mọi hệ thống.

Cách đọc: p95 server COMPILE lượt 1 = 115.353 ms nghĩa là khoảng 95% mẫu server_total_ms không vượt ngưỡng này; 5% còn lại có thể chậm hơn nhiều. Đây là latency bước /run, không gồm toàn hành trình upload→download và không bảo đảm SLA.

Cách ra quyết định
  • p95: chỉ số ưu tiên để so sánh mục tiêu độ trễ.
  • Mean: theo dõi latency trung bình mỗi request.
  • RAM: cân nhắc RSS toàn worker, nhất là sau idle; mức tăng 8–23% cần ngân sách phù hợp, không phải footprint riêng của cache.
  • Tiêu chí giữ cache không đổi: Mean và p95 của cả hai latency thực tế giảm ở cả hai lượt đầy đủ; bốn blocks/lượt là đơn vị lặp.

Hai lượt, 16 worker mới (mỗi slot 1 worker), concurrency 1; 4 block × 250 measured/nhóm/lượt; 5 warmup/worker (tổng 80 ngoài steady-state). requests.Session có tái sử dụng TCP; tracing/telemetry bật giống nhau. Warmup làm nóng runtime/cache, không đo cold-start hoặc tải đồng thời.
