Hãy tưởng tượng bạn bước vào một nhà hàng quen thuộc và gọi một món ăn cố định (gọi API thực thi pipeline):

Khách thứ hai, thứ ba, thứ một nghìn vào gọi đúng đĩa cơm đó... đầu bếp vẫn lặp lại đúng chu trình đánh vần và dịch sách đó từ đầu!

Vấn Đề 2: Warm Graph Fallback Khi Request Có File Tweaks

Giải thích Tweaks, điều kiện dùng Warm Graph và phần khởi tạo vẫn cần cho từng request

Graph Execution Bottleneck
📌 Graph Trong Langflow Là Gì?

Là toàn bộ luồng xử lý AI (Flow), gồm các bước xử lý (Nodes như ChatInput, SCRFD Model) và các đường dẫn truyền dữ liệu nối giữa chúng (Edges).

🔥 Warm Graph Có Tác Dụng Gì?

Registry giữ graph template trong RAM worker. Request đủ điều kiện dùng copy_for_run() để tạo graph riêng; vẫn dựng nodes/edges và component. Cơ chế này không loại bỏ toàn bộ khởi tạo hoặc cấp phát bộ nhớ.

Vấn đề Nhánh Main (Baseline) Nhánh Tối Ưu Của Bạn (Warm Graph)
Worker làm gì khi có khách gọi API? Worker phải đọc chuỗi JSON từ Database lên, dùng RAM của mình ngồi ráp lại từng node Graph, Vertex, Edge từ đầu. Worker giữ graph template trong RAM sau khi warm. Campaign đặt preload limit = 0 nên nạp khi cần trong giai đoạn warmup, không dựng sẵn từ startup.

Gánh nặng lên Worker? Cold path có công việc dựng graph và cấp phát object. Campaign chưa đo CPU/RSS hoặc trace GC nên chưa xác định nguyên nhân latency spike. 📦 COMPONENT COMPILATION CACHE ARCHITECTURE component_compilation_cache.py 
# 1. ĐỊNH NGHĨA ARTIFACT BIÊN DỊCH AN TOÀN TRONG RAM
@dataclass(frozen=True, slots=True)
class ComponentCompilationArtifact:
    source: str                     # Chuỗi source code Python gốc
    generation: int                 # Phiên bản generation hợp lệ
    module_template: bytes          # Template AST module đã serialize qua pickle
    class_name: str                 # Tên class Component (VD: SCRFDNode)
    compiled_class: CodeType        # Bytecode đã compile sẵn - nạp thẳng vào runtime
    trusted_vector_store_alias: str | None

# 2. BĂM SHA-256 CỦA SOURCE CODE ĐỂ LÀM KHÓA TRUY VẤN DUY NHẤT
def _source_digest(source: str) -> str:
    return hashlib.sha256(source.encode("utf-8", errors="surrogatepass")).hexdigest()

# 3. QUẢN LÝ CACHE TRONG RAM: THREAD LOCK TRÁNH RACE CONDITION + GIỚI HẠN LRU
_cache: OrderedDict[_CacheKey, _CacheEntry] = OrderedDict()
_cache_lock = RLock()  # Khóa luồng an toàn khi nhiều worker thread truy cập đồng thời

def get_or_build_component_artifact_with_status(source, builder, *, variant=""):
    key = (COMPONENT_COMPILATION_ARTIFACT_GENERATION, _source_digest(source), variant)
    with _cache_lock:
        cached = _cache.get(key)
        if cached is not None and cached.source == source:
            _cache.move_to_end(key)  # Đánh dấu vừa truy cập (LRU)
            return ComponentArtifactLookup(artifact=cached.artifact, retained=True)

        # Nếu chưa có (Cache Miss): chuẩn bị artifact rồi lưu; có thể miss lại sau eviction
        artifact = builder()
        _cache[key] = _CacheEntry(source=source, artifact=artifact)
        return ComponentArtifactLookup(artifact=artifact, retained=True)
ℹ️ Tính toàn vẹn: Khóa gồm generation, SHA-256 của source và variant; cache kiểm tra thêm source khớp entry. Source thay đổi sẽ không tái sử dụng artifact của source cũ. Đoạn code trên rút gọn phần cờ bật/tắt, giới hạn LRU và counter.

def report_migration(migration_report, *, flow_id, user_id,
                     emit_extension_events=True):
    for migration_error in migration_report.errors:
        logger.warning("extension migration: code=%s...", migration_error.code, ...)

    if emit_extension_events:
        try:
            from lfx.services.deps import get_extension_events_service
            _svc = get_extension_events_service()
            if _svc is not None:
                # 2. CÓ USER: PHÁT VÀO user:{user_id}; KHÔNG CÓ USER: global
                _keyspace = f"user:{user_id}" if user_id else "global"

                # 3. PHÂN BIỆT EVENT REWRITE VÀ DIAGNOSTICS
                if migration_report.any_rewritten:

                        "flow_id": str(flow_id) if flow_id else None,
                        "rewritten_count": migration_report.rewritten_count,
                    }, keyspace=_keyspace)
                for migration_error in migration_report.errors:
                    _svc.emit("extension_error", {
                        "flow_id": str(flow_id) if flow_id else None,
                        "code": migration_error.code,
                        "message": migration_error.message,
                        # Code thật còn gửi hint và location
                    }, keyspace=_keyspace)
        except Exception:
            # 4. BEST-EFFORT: LỖI EVENT BUS ĐƯỢC GHI LOG, KHÔNG CHẶN LOAD FLOW
            logger.warning("extension.event_emit_failed: ...", exc_info=True)

# 2. MINH HỌA INTERVAL UNION (logic thực nằm trong protocol.measure_overhead)
def interval_union_ms(intervals: list[tuple[float, float]]) -> float:
    total = 0.0
    right = float("-inf")
    for start, end in sorted(intervals):
        total += max(0.0, end - max(start, right))
        right = max(right, end)
    return total  # Hợp các khoảng output method của 4 node SCRFD; interval tính bằng ms

Chọn p95 Làm Chỉ Số Ưu Tiên Như Thế Nào?

Giảm overhead ở phần chậm của phần lớn request; dùng mean và p99 để kiểm tra sự đánh đổi

p95 + mean + p99
Vì sao chọn p95?

Mục tiêu là giảm thời gian điều phối của phần lớn request, kể cả những request chậm hơn mức điển hình. p95 bổ sung thông tin mà mean không thể hiện. Đây là lựa chọn theo mục tiêu đề tài, không phải chỉ số tốt nhất cho mọi hệ thống.

Cách đọc: p95 = 68.61 ms nghĩa là khoảng 95% mẫu overhead không vượt ngưỡng này; 5% còn lại có thể chậm hơn nhiều. Đây không phải latency end-user hay bảo đảm SLA.

Cách ra quyết định
  • p95: chỉ số ưu tiên để so sánh mục tiêu độ trễ.
  • Mean: theo dõi overhead trung bình mỗi request.
  • p99: kiểm soát request rất chậm; ngưỡng chấp nhận phải dựa trên yêu cầu ứng dụng và chốt trước lượt xác nhận.
  • 1.000 mẫu/arm: 1% tương ứng khoảng 10 request. Cần lặp lại trước khi kết luận chắc chắn về p99 hoặc khoảng cách p95 nhỏ.
Điều kiện đo và biến thiên

16 worker mới (mỗi slot 1 worker), concurrency 1; 4 block × 250 mẫu/arm, 5 warmup/slot (80 warmup ngoài thống kê). HTTP connection reuse tắt ở mọi arm. Không đo cold-start hoặc tải đồng thời.

Giữa 10 và 11: 11 có p95 thấp hơn ở block 1, 4; 10 thấp hơn ở block 2, 3. p95 tổng hợp tính trên 1.000 mẫu/arm, không lấy trung bình percentile từng block. Dùng nội suy tuyến tính (Hyndman–Fan type 7).
